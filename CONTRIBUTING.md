# Coding standards

Use Node.js 22.12+ and ES modules. Prefer named exports, descriptive camelCase functions/variables, PascalCase types/classes and UPPER_SNAKE_CASE constants. File names use kebab-case. Keep external YAML property names unchanged. Use four spaces, single quotes, semicolons and 100-column formatting via Prettier. Use ESLint recommended rules and avoid eval, implicit globals and unused variables. Do not introduce domain-specific entity lists or node coordinates.

Prefer small pure functions for model transformations and geometry. Keep parsing, graph calculation, rendering and UI events separate. Explicitly pass dependencies to feature factories; avoid new cross-feature global state. Validate at the import boundary and provide actionable errors. Never silently discard mappings. Use textContent for user-supplied strings. Do not log or commit source SQL, private YAML, credentials or tokens.

For each change, add regression tests for changed behavior. Before committing:

```sh
npm run format
npm run format:check
npm run check
npm run test:coverage
```

Use a focused pull request and review validation, dependency changes, accessibility and runtime impact. CI runs lint, unit tests, build and coverage reporting. Formatting is a contributor check until the initial Prettier baseline is generated. Commit the package-lock.json generated by npm install to enable reproducible npm ci installs. Do not commit node_modules or dist. Avoid making unrelated framework migrations in feature PRs.
